# 无人深空 · 电力模拟器（NMS Power Sim）

一个**纯静态、零依赖、离线可用**的单页 Web 应用，用来讲解 + 仿真《无人深空》基地建造里的
电力逻辑元件（电源、太阳能板、墙壁开关、邻近开关、按钮开关、地面开关、自动开关、能量逆变器），
并内置 7 个可直接上电运行的应用实例电路。

> ⚠️ 直接双击 `index.html` 无法运行：应用使用 ES Module（`type="module"`），
> 在 `file://` 协议下会被浏览器的同源策略拦截。请使用下方的启动脚本。

---

## 快速开始

**Windows**：双击 `start.bat`

**macOS / Linux**：`./start.sh`

脚本会启动一个本地静态服务器并自动打开浏览器：

- 默认端口 **8900**（同目录其它项目使用 8899，故本项目避开）；若被占用会自动 +1。
- 优先使用 `python` / `python3` 的 `http.server`，没有则回退到 `npx serve`。
- 关闭终端窗口即停止服务。

## 元件语义（本项目实现口径）

- **电源**：恒通电，是网络的源。
- **太阳能板**：仅在**白天**（06:00 ≤ 时刻 < 18:00）向网络供电，入夜即停止。
  昼夜切换是**即时**的（无 1 秒延迟）；图标格栅白天发亮、夜晚压暗，右下角指示灯绿=供电 / 红=停止。
- **输出端（灯柱）**：通电即亮。
- **普通电门**：**通电 = 关闭（拦截），断电 = 打开（通行）**。
- **墙壁开关**：手动开关，点击翻转。
- **邻近开关**：玩家令牌进入圆形感应半径（默认 130px，可调）即导通。
- **按钮开关**：默认切断，触发后接通 1 秒再自动弹起。
- **地面开关**：玩家令牌站到板面感应区上即导通。
- **自动开关**：两个侧端口 a/b 是同一开关的两端（导通时短路、切断时隔离）；
  顶部 `ctrl` 为独立的只读控制端；**a↔b 导通状态 = 控制端信号的「延迟 1 秒跟随」**。
- **能量逆变器**：同上，但 **a↔b 导通状态 = 控制端信号的「延迟 1 秒取反」**。

「延迟」= 目标值变化后必须**连续保持 1 秒**才真正切换；中途目标又变回去则计时清零。

### 昼夜时间系统

- 游戏内一整天 = **60 真实秒**（`DAY_LENGTH_SECONDS`，随仿真速度倍率缩放）；
  日出 06:00（`DAY_START_HOUR`）、日落 18:00（`DAY_END_HOUR`），起始时刻 **08:00**。
- 工具条「时刻」滑块可直接跳到任意时刻（即时生效，暂停状态下同样生效）；
  「昼夜循环」勾选后时间才会自动流逝，取消勾选则时间冻结。

### 导线配色约定（与素材相反，本项目有意为之）

- **蓝线 = 通电导线**（`--wire-on: #2ea8ff`）
- **红线 = 未通电导线**（`--wire-off: #c2413f`）
- 元件端口指示灯仍遵循素材规则：**绿 = 接通，红 = 切断**（与导线配色是两回事）。

## 仿真内核说明（`js/engine.js`）

每帧 `tick(dt)` 的执行顺序**严格固定**，用「上一帧的通电集合」做采样，天然打破代数环：

1. **采样**：读取每个延迟元件 `ctrl` 端（上一帧）的通电状态。
2. **推进定时器**：算出 `target`（自动开关为 ctrl 通电值；逆变器为其取反），
   与当前 `conducting` 不同则累加计时，满 1 秒即切换；相同则清零。
   手动元件按各自即时条件置位。
3. **并查集求通电集合**：节点 = `elId:port`；合并边 = 所有导线 + 所有导通元件的 a-b 内部边；
   处于「可供电」状态的源元件 `out` 端口所在连通分量整体标记为通电
   （恒电源恒可供电；太阳能板仅白天可供电，故夜间其网络整段断电、切换无延迟）。
4. **更新设备**：`lamp.lit = in 端通电`；`door.open = !in 端通电`；
   `solar_panel.supplying = 白天`。

并查集（路径压缩）天然支持环路 / 反馈，不会死循环或栈溢出。
主循环使用 `requestAnimationFrame`，固定步长 `1/60 s`，单帧最多补算 20 步。

公开 API：`createEngine()`、`addElement`、`removeElement`、`addWire`、`removeWire`、
`tick(dt)`、`getNodePowered(elId, port)`、`getElementView(elId)`、`serialize()` / `serializeJSON()` /
`deserialize()`、`reset()`、`getTimeOfDay()` / `setTimeOfDay(h)` / `getIsDay()` /
`getDayCycle()` / `setDayCycle(b)` 等。

导出常量：`SOURCE_TYPES`（含 `solar_panel`）、`DAY_LENGTH_SECONDS`、`DAY_START_HOUR`、`DAY_END_HOUR`。

## 画布视图与导线路由（本轮新增）

- **视图变换**：`<g class="viewport" transform="translate(tx ty) scale(k)">` 包裹全部图层；
  元件 / 端口的「世界坐标」语义不变（初始 `k=1, tx=0, ty=0`），
  `board.clientToWorld()` 负责屏幕 → 世界换算，放置 / 拖动 / 连线 / 拖令牌全部自动正确。
- **正交路由**：两端各沿端口朝向出 26px stub，中间按朝向组合走 Z 形或 L 形折线，
  随后去掉连续重复点与共线中间点；输出路径只含 `M` / `L` / `A`。
- **交叉拱**：所有导线两两求「一横一竖」的交点（距端点 > 12px 才有效），
  交叉点归 **id 数值较大**的那条线，在该处以 `R=7` 半圆弧「跨过」；同一段内多点按参数排序处理。
- **halo 底衬**：每条导线先画一层 10px 暗色衬底（`#05090c`）再画 4px 彩线，
  交叉处下层线被上层衬底切断，交叉点分层可辨。

## 已知限制 / 设计取舍

- **实例 2、实例 3 的自动开关采用「电源母线 + 控制端级联」接法**：
  三个自动开关的输入 a 直接接常备电源（母线），信号则沿各元件的**控制端 ctrl** 逐级传递，
  末级输出反馈回首级控制端形成闭环。之所以这样接：若把输入 a 也串成一条链，
  由于自动开关「导通时才把 a-b 短路」，输入一断输出会**立即**断电（下降沿不延迟），
  灯会在半周期熄火、周期被压缩。改用电源母线后，输出 = 控制信号的纯延迟，
  才能得到实例 3 所要求的「4 级 × 1 秒 × 2 = 8 秒」稳定追逐。
- **实例 2 的一个细节**：按钮的启动信号与末级输出「反馈线」接在同一个控制端节点上，
  而该节点同时连着第三盏灯，因此**按下按钮的瞬间第三盏灯会短暂点亮**（约 1 秒）——
  这与该接法的实际电路一致，随后即进入 l1→l2→l3 的循环。
- **实例 4（密码门）说明**：教程图中自动开关 2 / 4 的控制端经逆变器接墙开，
  需要墙开自身也接电源才能把「通/断」送入逆变器控制端；已补齐该电源线。
- **实例 5（双控）说明**：教材原文给出的建议接法在本项目语义下会让灯恒灭，
  故按素材「两列 + 中间 X 交叉」的意图改用**能真正实现 XOR** 的等价接法
  （两支路分别为「墙开1 且 非墙开2」与「墙开2 且 非墙开1」，并联）。
- **按钮脉冲与 1 秒延迟**：按钮接通 1 秒、延迟元件判定阈值同为 1 秒，两者临界。
  内核用「半个步长的浮点余量」判定延迟，并使按钮恰好占满 60 个采样帧，
  以保证单独一次按钮就能可靠驱动延迟链（不会因浮点误差少 1 帧而漏触发）。
- 元件图鉴共列出 **11 张卡片**（含「太阳能板」与「玩家令牌」这类非电气辅助元素），比需求中的 9 张多 2 张。
- 已实现画布**滚轮缩放 / 空格与中键拖拽平移 / 适应视图**；仍未实现框选、撤销 / 重做（需求中标注为可省略）。
- 交叉拱的归属固定为「导线 id 数值较大者起拱」；若同一小段内密集出现多个交叉，拱之间可能视觉相叠（本项目的实例中未出现）。
- 邻近 / 地面开关的感应仅由「玩家令牌」驱动，未实现「瞬时强制」按钮（需求中标注为可选）。
- 元件图标为依据素材重绘的简化内联 SVG，非素材原图逐像素复制。
- 工作区 `assets/` 实际为 **20 个**文件（需求书写为 21 个），已全部原样保留、未做改动。
